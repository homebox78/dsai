# 개발자 가이드 — 소스 구조와 규칙

처음 이 저장소를 여는 개발자가 **어디를 고쳐야 하는지** 5분 안에 찾을 수 있게 정리한 문서입니다.
각 소스 파일 맨 위에도 같은 내용의 짧은 docblock이 달려 있습니다.

---

## 1. 큰 그림

```
main.tsx → App.tsx (라우트 3개뿐)
             ├── /login   LoginPage      로그인·회원가입·2FA (탭 전환)
             ├── /setup   SetupPage      최초 1회 온보딩 3스텝
             └── /        EntryGate → AppShell  ←── 여기가 사실상 앱 전부
                            ├── AppHeader      상단 바 + 드롭다운 3종
                            ├── SideMenu       좌측 메뉴 (그룹 접기/펴기)
                            ├── ScreenRouter   본문 — screen 값에 따라 뷰 교체
                            ├── LayerHost      모달·시트 전부 (겹쳐 뜸)
                            └── QaBar          검수 플로팅 바
```

**진입 동선** (클라이언트 검수용): 처음 접속하면 무조건 `/login?tab=login` → 로그인하면 **작업목록(검수 인덱스)** 착지 → 각 화면.
게이트는 [session.ts](../src/lib/session.ts) 의 sessionStorage 플래그 하나뿐이다(실제 인증 없음).
탭을 새로 열거나 로그아웃하면 다시 로그인부터. 로그인 전에 `#screen=...` 딥링크로 들어오면 그 해시를 기억했다가 로그인 후 복원한다.

**화면 운영 원칙**: 페이지를 늘리지 않는다. 상세·설정·요청은 전부 레이어(모달/시트)로 연다.
새 화면을 만들고 싶으면 라우트가 아니라 `ScreenKey` 를 늘린다.

## 2. 상태는 zustand 스토어 3개

| 스토어 | 파일 | 무엇을 담나 |
|---|---|---|
| `useAppStore` | [app-store.ts](../src/stores/app-store.ts) | 지금 보고 있는 화면(`screen`), 선택된 폴더·파일·룸·업무, 드롭다운 열림, 검수 프리셋 |
| `useLayerStore` | [layer-store.ts](../src/stores/layer-store.ts) | 열려 있는 레이어 스택. `open('file-upload')` 하나로 연다 |
| `useDataStore` | [data-store.ts](../src/stores/data-store.ts) | **실제로 변하는 데이터** — 폴더·파일·멤버·업무·메시지·자료요청 (인메모리 CRUD) |

`mocks/data.ts` 는 **초기 시드값**이다. 화면에서 추가·삭제한 결과는 `data-store` 에 쌓인다.
새로고침하면 시드로 돌아간다 (DB 미연결).

## 3. 화면 추가/수정하기

1. `app-store.ts` 의 `ScreenKey` 에 키를 추가
2. `views/<도메인>/XxxView.tsx` 작성
3. `ScreenRouter.tsx` 에 매핑 한 줄
4. 메뉴에 넣으려면 `SideMenu.tsx` 의 `GROUPS` 에 항목 추가

## 4. 레이어(모달/시트) 추가하기

1. `layer-store.ts` 의 `LayerKey` 에 키 추가
2. `LayerHost.tsx` 안에 컴포넌트 작성 후 최상단 목록에 `<Xxx />` 추가
3. 폼이면 직접 만들지 말고 **`FormModal`** 에 `fields` 배열만 넘긴다 — 검증·레이아웃이 딸려온다

```tsx
<FormModal
  id="folder" title="폴더 만들기" cta="만들기"
  fields={[{ label: '폴더 이름', type: 'text', required: true, placeholder: '예: 인증서' }]}
/>
```

`type` 은 `text | area | select | chips | readonly | invite`.
검증은 **라벨 이름으로 자동 추론**된다(이메일·URL·사업자번호·이름 길이 등, [validate.ts](../src/lib/validate.ts)).
다르게 하고 싶으면 필드에 `rules: [...]` 를 직접 지정 — 명시하면 기본 길이 규칙은 붙지 않는다.

## 5. 꼭 알아야 할 관례

### `useQaState` vs `useState`
```ts
const [tab, setTab] = useQaState('zoneTab', 'task')  // 검수 인덱스가 재현해야 하는 상태
const [query, setQuery] = useState('')               // 그냥 입력값
```
검수 인덱스(116항목)에서 특정 상태를 열어 보여줘야 하는 값만 `useQaState` 를 쓴다.
프리셋에 없는 키는 기본값으로 리셋되므로 항목 간 상태가 섞이지 않는다.
**검수 전용 배선이며, `npm run remove-qa` 로 `useState` 환원까지 자동 처리된다** (아래 7장 참조).

### 아이콘
Material Symbols만 쓴다. `<Icon name="folder" size={17} />`
직접 그린 SVG·이모지·문자 글리프(‹ › ✕ ▼)는 금지. 아이콘만 있는 버튼에는 반드시 `title` 을 준다(스크린리더가 리거처 원문을 읽는다).

### 셀렉트
네이티브 `<select>` 금지. `components/common/select.tsx` 를 쓴다 — 트리거와 같은 폭으로 열리고, 아래 공간이 모자라면 자동으로 위로 뒤집힌다([flip-up.ts](../src/lib/flip-up.ts)).

### 표 정렬
헤더는 전부 가운데. 셀은 — 금액·수치 우측 / 길이가 들쭉날쭉한 문장·이메일 좌측 / 그 외 가운데.

### 높이
화면 본문의 인풋과 버튼은 **34px** 로 맞춘다. 버튼 라벨은 전역 CSS로 `white-space: nowrap` — 여러 줄이 필요하면 `whitespace-normal` 로 덮어쓴다.

## 6. 폴더별 역할

| 경로 | 역할 |
|---|---|
| `components/ui/` | **shadcn 원본**. 되도록 직접 수정하지 않는다 (아이콘만 Material Symbols 로 교체됨) |
| `components/common/` | 프로젝트 공용 부품 — Icon, Select, ChoiceRow(라디오 한 줄), FileExt(확장자 아이콘), DocPreview(실제 PDF/XLSX/DOCX 렌더), ChatbotPanel, QaBar, DotCube(로그인 배경) |
| `components/layout/` | 셸 골격 — AppHeader, SideMenu, Breadcrumb, MegaMenu(전체 메뉴), WsPopover, PanelHandle |
| `components/layers/` | 모달·시트. `Modal.tsx` 가 껍데기, `FormModal.tsx` 가 폼 생성기 |
| `views/` | 화면 본문. 도메인별 폴더 |
| `lib/` | session(진입 게이트), qa-state(검수 프리셋), hash-sync(딥링크), flip-up(드롭다운 방향), validate(검증), responsive(반응형 수치), ai-simulator |
| `mocks/data.ts` | 시드 데이터 + 상태 색상 톤 맵 |

## 7. 검수(QA) 도구 — ⚠️ 검수 완료 후 삭제

- 화면 우하단 **검수 바**로 115개 항목을 순회할 수 있다
- 콘솔에서 자동화: `window.__qaCount` (개수), `window.__qaOpen(i)` (i번 항목 열기)
- 주소로 바로 열기: `#screen=store&modal=file-upload`
- 항목 정의는 [index-data.ts](../src/views/index/index-data.ts) (시안 dc.html 에서 생성)

### 검수가 끝나면 한 줄로 제거
```bash
npm run remove-qa -- --dry   # 미리보기
npm run remove-qa            # 실제 제거
npm run build                # 확인
```
작업 목록 화면 · 검수 바 · 프리셋 배선을 지우고 `useQaState` 를 `useState` 로 되돌린 뒤,
로그인 착지 화면을 대시보드로 바꾼다. 해시 딥링크와 로그인 게이트는 남는다.

## 9. 클라이언트 검수 안내
