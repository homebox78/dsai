> **Amber Document Intelligence** (Private AI for Enterprise Knowledge, EvolvAiLab)의
> 프론트 오피스 화면을 **DB 없는 프론트엔드 목업**으로 제작하는 프로젝트.

## 1. 프로젝트 이해

### 무엇을 만드는가
- 기업 내부 문서를 AI로 관리·검색·활용하는 **엔터프라이즈 문서 지식 콘솔**의 프론트 화면 전체.
- 백엔드·DB·실제 AI 연동 없이, **실제 서비스처럼 동작하는 느낌의 목업**까지가 납품 범위.
  - 화면 전환, 모달/드롭다운/시트 인터랙션, 접기/펼치기가 전부 실동작
  - 폴더 추가·업무요청 등 CRUD는 메모리(스토어)에서 실반영
  - AI 응답(챗봇·문서 요약·증빙 검색)과 OCR/RAG 처리 진행률은 **시뮬레이션 연출**

### 데이터 계층 (시스템 뼈대)
```
조직(Organization) → 조직&사업부(Workspace) → 프로젝트(Project)
                                                └─ 문서 저장소 / 파일 / 채팅방 / 업무(Task) / EcoVadis / AI 로그
```
- 각 단계는 독립 저장되며, 이전 단계의 id가 다음 단계의 부모 키
- 최초 관리자 접근 시 조직>조직&사업부>프로젝트가 없으므로 **별도 페이지(모달 아님) 3단계 셋업**으로 생성 — 1회성, 향후 모달 대체 예정
- 화면 표기: "워크스페이스" → **"조직&사업부"** 로 치환 (스토리보드 p9 지시)

### ⚠️ 화면 운영 원칙 (2026-07-25 클라이언트 지시)
- **페이지를 여러 개 만들지 않는다.** 되도록 **한 화면 안에서 동선이 운영**되게 —
  모달·시트(열고 닫기)·패널 펼치기/접기 등 **동적으로 레이어에 정보를 불러오는 방식**이 기본.
- 라우트는 최소화(인증 / 초기 셋업 / 앱 셸 정도), 앱 진입 후에는:
  - 메뉴 선택 = 페이지 이동이 아니라 **셸 안의 컨텐츠 영역 교체**
  - 상세·설정·요청·미리보기 = **모달/Sheet/하단·우측 패널로 겹쳐서** 표시
  - 목록↔상세↔뷰어↔챗봇이 **같은 화면 안에서** 전환 (스토리보드 p39·46 구조 그대로)
- 딥링크(`?view=`·`?modal=`)는 유지하되, 새 페이지가 아니라 **같은 셸 위에 해당 레이어를 여는** 방식

### ⚠️ 언어 기준 (2026-07-25 클라이언트 확인)
- 스토리보드의 **영문 캡처는 이해를 돕기 위한 참고용 레퍼런스일 뿐**
- **한글로 적어준 메뉴·명칭이 실제 표기 기준**이며, **실제 제작은 전 화면 한글**
- 영문 라벨(Organization setup, Upload files, Complete Task 등)은 전부 한글 번안, 애매한 용어는 용어집으로 확정 후 진행
- 목업 데이터(조직명·프로젝트명·인물)도 한글 세계관으로 구성

## 2. 화면 구성 이해 (스토리보드 63p 분석)

### 공통 레이아웃
- **형태1**: 헤더 / 경로(breadcrumb) / [메뉴 | 서브메뉴 | 컨텐츠 | 컨텐츠&챗봇] 4단
  - 세 패널 모두 **숨기기/펼치기** — 메뉴 숨김 시 아이콘만, 축소 시 확대 아이콘 노출
  - 영역 구분은 카드가 아닌 **라인(divider)**, 블루-그레이 톤 유지
- **형태2**: 헤더 / 경로 / [메뉴 | 컨텐츠 | 컨텐츠] 3단
- 경로 영역: breadcrumb + 배지(파일 수·RAG% 등) + 우측 액션 버튼
- 헤더 아이콘: 조직&사업부 스위처(N) · 도움말(?) · 설정(⚙, 페이지 이동) · AI(✦, 우측 Sheet) · 알림(🔔) · 프로필 — 전부 드롭다운/시트
- 조직/조직&사업부/회원추가는 전부 **모달**

### 프로젝트 좌측 메뉴 (한글 확정 명칭)
```
[조직&사업부 영역] > [프로젝트 영역] >
# PROJECT      : 대시보드 · 멤버
# 협업공간      : 채팅1 · 채팅2 · 채팅3 · 업무        (뱃지 카운트)
# 문서         : 문서 저장소 · 문서
# EcoVadis     : 요약 · 문항 · 증빙자료 · 자료요청
# SYSTEM       : 멤버등록
```

### 도메인별 이해

| 도메인 | 이해한 내용 |
|---|---|
| **인증** | 로그인·회원가입·아이디/비번 찾기·2FA. 블루 컨셉 |
| **초기 셋업** | 조직 → 조직&사업부 → 프로젝트 3단계 페이지(스텝 레일 + 폼 + 데이터 출력 패널) |
| **파일관리** | 폴더 트리 + 파일 목록 **2종**(용도 다름, 겹칠 수 있음 — 개발 단계에서 분리 사용 예정) + 파일 요약 패널. 파일 상세 = AI 요약(숨기기/보기) + 상태 배지 + react-pdf/이미지 뷰어 + 문서 챗봇. 폴더 추가·파일 업로드(AI 인덱싱 토글)·새 파일(doc/hwp/md)은 모달. 파일 작성기 = 목차 + 에디터 + AI 어시스턴트(**삽입 위치 드롭다운**: 현재 커서/새 문단/선택 문단 아래/선택 영역 교체/문서 끝/제목/표) |
| **챗봇 영역** | 목록 단계 = 폴더 내 파일을 AI로 찾는 용도 / 문서 보기 단계 = 문서 내용 안에서 찾기·서포트 용도. 검색 요약이 챗봇 영역에 뜨고 파일 클릭 시 상세로 이동 |
| **채팅+업무(Task)** | 채팅룸 목록 + 룸 상세 + 우측 업무 존(채팅↔Task **탭 전환**, 룸 안에서는 항상 열림). 업무 = 다른 유저가 나에게 업무/파일을 요청하면 처리·전달·완료하는 영역. 완료되면 종료. 멤버 클릭 → 정보보기/채팅하기/업무요청. 업무요청은 우측 **Sheet**. 외부 협업자 초대(이메일/링크 — 만료 7일/30일/없음, 권한 편집/보기/댓글). Task 미리보기 모달(미리보기/버전/활동 3탭) |
| **업무 관리 페이지** | 워크플로 상태(요청됨→진행중→검토→완료) + 업무 목록 + 상세(타임라인·증빙 업로드·코멘트) + 우측 실시간 스트림(재요청 방지용 히스토리, 향후 상단 버튼+Sheet화) |
| **EcoVadis** | ESG 평가기관. 200~300개 질문항 질문지 업로드 → OCR(수정 가능해야 함) → 지정 폴더에서 AI가 답변 증빙 검색(파일명·페이지 표시, 수작업 등록도 가능) → 못 찾으면 챗봇(RAG)으로 → 그래도 없으면 담당자에게 자료요청(Task) → 답변 완료. 진행률 = AI 초안/미처리/답변완료 합산 100%. 결과는 **1개 파일로 다운로드**. 컨텐츠 영역은 업무 메뉴를 떼어 재구성 |
| **대시보드** | 4섹션 서머리(사업부 현황/프로젝트&업무/문서 파이프라인/AI 워크스페이스) — 내가 할 일과 상태를 한눈에 |
| **전체 메뉴** | 헤더 드롭다운 → 화면 전체를 덮는 메가메뉴. 전 메뉴 + 내가 해야 할 일을 한 번에 보고 이동 |
| **관리자** | 사용자관리 · 워크스페이스 · 멤버 관리 · 채널관리 (폼+테이블 패턴) |
| **계정** | 내 정보 · 보안 및 로그인(2FA 토글, 로그인 기록) |
| **우측 위젯** | AI 처리 상태 카드(단계별 진행률·남은 시간) · 외부 협업자(관리 모달) · 최근 활동(전체 모달) · 스토리지 게이지 |

### 범위 제외 (클라이언트 Aiden 직접 제작 명시)
- 도움말 드롭다운의 상세 페이지 4종(사용가이드/도움말/약관·정책/고객센터 — **드롭다운까지만** 구현)
- 파일 작성 **목차 편집 페이지** (p44 "이 페이지는 제가 만들어요")

## 3. 기술 스택

- **React 19 + Vite + shadcn/ui + Tailwind v4** (확정)
- react-router v7(**최소 라우트** — 인증/셋업/앱 셸) · zustand(목업 상태 + **레이어/뷰 상태**) · react-pdf(뷰어) · Pretendard

- 원칙: 디자인 토큰 단일 진리원(hex 하드코딩 금지) · 네이티브 select 금지 · 같은 줄 컨트롤 높이 통일 · 모달/탭 딥링크(`?modal=`·`?tab=`)로 검수 동선 제공

## 5. 착수 전 확인 필요

1. **반응형 범위** — 데스크톱 1920 기준(1280 안전 축소)으로 가정. 모바일 대응 여부 확인
2. **문서 작성기 깊이** — 목업은 경량 에디터로 흐름 재현(실 편집기는 개발 단계). TipTap 도입 여부는 옵션
3. 번안 애매 용어 용어집(Store→저장소, RAG Index 표기 등) — Phase 0에서 확정
